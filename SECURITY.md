# Security policy

## Report a vulnerability privately

Do not disclose a suspected vulnerability in a public issue, discussion, or pull request.

Use [GitHub private vulnerability reporting](https://github.com/Inima-solution/INIMOA/security/advisories/new) and include:

- affected commit or version;
- affected component and deployment assumptions;
- reproduction steps or a minimal proof of concept;
- expected and observed impact;
- any suggested mitigation.

Avoid accessing data you do not own, disrupting a live service, or retaining sensitive data while testing.

## Scope and project status

INIMOA is under active development and does not currently publish a production-support or security-certification claim. Certifications, bug-bounty terms, and security statements made by Macro for its hosted service do not automatically apply to this independent fork.

Security fixes should include focused regression coverage and should not include credentials, production records, or exploit data that would expose users.
